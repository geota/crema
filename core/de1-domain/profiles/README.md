# Built-in DE1 profiles

`builtin.json` holds Crema's built-in profiles in Crema's **native** format: a
JSON array of `Profile` (the `de1-domain` model). It is embedded into the
`de1-domain` crate at compile time (`include_str!`) and exposed as built-in
Crema `Profile`s by the [`builtin`](../src/builtin.rs) module.

The profiles are the 88 standard espresso/tea/cleaning profiles shipped by the
**de1app** project — the original Decent Espresso DE1 tablet application
(`de1plus/profiles/`) — plus "Adaptive v2", which de1app replaced with
"Adaptive v3" in the same file (so it comes from `best_practice.tcl` as of
before de1app 1a61f9b4). Each upstream `*.tcl` file is converted via
`de1_domain::import_legacy_tcl`, and the resulting `Profile`s are serialized
into `builtin.json` (see Regenerating). The upstream `.tcl` files are *not* vendored as
shipped data; `builtin.json` is the only embedded data file. (Two upstream `.tcl`
profiles are retained under `tests/fixtures/` purely as legacy-import parser test
inputs — see [`THIRD-PARTY-NOTICES.md`](../../../THIRD-PARTY-NOTICES.md).)

## Origin

- Upstream project: <https://github.com/decentespresso/de1app>
- Path in upstream: `de1plus/profiles/` (the `*.tcl` profile files)

## Regenerating

`builtin.json` is regenerated by importing every de1app `*.tcl` profile and
serializing the `Vec<Profile>` to JSON — the `gen-builtin-profiles` binary does
exactly that (files sorted by file name, `import_legacy_tcl` on each,
`serde_json::to_string_pretty`, trailing newline) and keeps every built-in's
stable `id` by matching titles against the current file:

```sh
cd core
# de1app main replaced "Adaptive v2" with "Adaptive v3" in best_practice.tcl
# (de1app 1a61f9b4); Crema ships both, so pass the v2 revision alongside.
git -C ../../crema-design/de1app show 1a61f9b4^:de1plus/profiles/best_practice.tcl \
    > /tmp/best_practice-v2.tcl
cargo run -p de1-domain --bin gen-builtin-profiles -- \
    ../../crema-design/de1app/de1plus/profiles /tmp/best_practice-v2.tcl
```

Never hand-edit `builtin.json`: fix the importer (or the upstream source) and
regenerate, so the file always equals what the importer makes of de1app.
